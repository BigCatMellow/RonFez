# Whole-show archive map

## Purpose

A major forensic bottleneck in this project is not always lack of surviving audio. In many cases the complete broadcast **does survive**, but it is buried in enormous month/year collections without segment-level indexing.

This file separates:

1. **Does the tape exist?**
2. **Where is it indexed?**
3. **What question do we need the tape to answer?**
4. **Has anyone actually listened/indexed the relevant segment yet?**

The current highest-value public index is Fourble's *Ron and Fez* feed, which points its individual episodes to files hosted by **Internet Archive**.

Primary index:
- https://fourble.co.uk/podcast/ronfezfixedepisodetitles

Fourble describes the collection as *Ron and Fez*, “US talk radio show,” sourced from archive.org.

# Fourble as an index, not a primary transcript

Fourble is extremely useful but should be described accurately.

It establishes:

- an episode/date entry exists;
- an audio file is linked;
- file size;
- broad collection coverage.

It does **not by itself establish**:

- that the date metadata is error-free;
- that the file is complete from first second to sign-off;
- what happens inside the episode;
- who originally recorded/uploaded it;
- whether rebroadcast material is mixed into some dates.

For content claims, the audio itself remains the primary evidence.

---

# Known archive oddities

The Fourble index contains some duplicate dates and variable file sizes, especially in portions of 2009 and other years.

Examples visible in the index include duplicate entries for some February 2009 dates.

Therefore future automation/indexing should not assume:

`one calendar date = exactly one unique canonical file`.

Each item needs:

- archive identifier;
- filename;
- duration;
- checksum if downloaded;
- audio start/end time;
- rebroadcast/duplicate status.
